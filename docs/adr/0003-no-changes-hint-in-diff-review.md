# Diff Review surfaces a no-changes hint instead of vanishing silently

When a Transform (quick action) or Advisor Fix stream finished with `correctedText === originalText`, `commitIfUnchanged()` immediately reset the workspace to the editable state in the same tick, unmounting `<DiffViewer>` before its `noChanges` branch could paint — so from the user's perspective the streaming spinner simply vanished and the editor reappeared with no explanation. A second, related bug hid behind this: an *empty* stream (`correctedText === ""`) never satisfied the equality check, so the user was left stuck in a diff view showing the entire text struck through. We removed `commitIfUnchanged()` from both streaming paths and instead keep the workspace in `diff-review`, letting the DiffViewer distinguish two terminal states via `isErrorState` (stream ended with empty corrected text for non-empty input → amber "Something went wrong. Try again.") and `isNoChangeState` (no change hunks → positive "All good! textmate found nothing to change."), each paired with a "Back to text" button that emits `dismiss`, which the parent forwards to a new `useWorkspace.exitDiffReview()` (a thin wrapper over `commitDiff(originalText)`). The trade-off is that the user must now explicitly dismiss a no-result diff rather than being dropped back into the editor, and because `exitDiffReview` reuses `commitDiff`, a no-op Fix dismiss still clears advisor threads (ClearThreadsCommand) for parity with the previous behavior — this is preserved deliberately but is worth revisiting, since a "nothing to change" result arguably means the issue threads are still valid. **Update:** `commitDiff` now gates `ClearThreadsCommand` on whether the resolved text actually differs from the original, so a no-op, empty/error, or fully-rejected Fix (paths that route through `exitDiffReview` or `commitResolved` with the original text) leaves advisor threads intact while a genuine rewrite still clears them.
