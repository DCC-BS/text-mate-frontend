# Collapse the Rewrite/Advisor tool split into a single ribbon-driven workspace

The app previously had two top-level workspaces — Rewrite and Advisor — where switching tool was the primary navigation act and gated whether the Editor was editable (a hard read-only lock came on as soon as the Advisor ran). We are collapsing both into a single centered Editor driven by a Word-style ribbon with two tabs (Transform, Validate), and replacing the rigid six-phase advisor lifecycle (`edit → reviewing → review → fixing → diff → done`) with a two-state model: the Editor is **Editable** by default, or locked for a **Diff Review** (plus transient progress overlays while a stream runs).

We picked this over three real alternatives: (a) keep Tool as hidden internal state with the UI toggle removed — rejected as likely-to-rot; (b) keep the six-phase machine and just reorganize the chrome — rejected because it contradicts the goal of letting the user edit while violations are visible; (c) make the Transform diff cancelable while the Validate diff hard-locks — rejected as asymmetric and confusing.

Consequences worth flagging for future readers: there is now one unified editor factory (the old `useRewriteEditor` + `useAdvisorEditor` merge), the `ToolSwitchCommand`/`ToolSelectView`/`TextTools` types are gone, Violation Ranges reflow through ProseMirror position-mapping and auto-dismiss when their text is deleted/replaced, User Threads survive a Check, the onboarding tour was rewritten, and the Editor Lock is no longer category-bound — it fires only during a Diff Review.
